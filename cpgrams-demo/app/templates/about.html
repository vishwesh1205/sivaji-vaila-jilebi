About this educational replica

A local, unofficial CPGRAMS-inspired portal built to demonstrate form design, complaint persistence and status timelines.

STUDENT PROJECT
NOT A GOVERNMENT SERVICE

Purpose

This project recreates the public-facing layout and essential citizen flows of India's Centralised Public Grievance Redress and Monitoring System (CPGRAMS) for education, interface research and full-stack demonstration. It is not a government service and must not be used to submit a real complaint.

The visual hierarchy — a reference-style identity strip, masthead, maroon navigation, hero carousel, about/What's New columns, quick-action cards and a dark footer — was studied from the official reference pages, then rebuilt with original markup and locally created assets.

What is real in this project

  • The web application runs locally and all navigation and forms work.
  • Demo complaints are genuinely persisted in a local SQLite database.
  • Registration numbers are generated transactionally and constrained to be unique.
  • Status timelines, reminders, feedback and exports reflect the stored rows.
  • Server-side validation and accessible error states are implemented.
  • Hindi and Tamil translations are provided for core navigation and messages.

What is simulated or different

  • No department, ministry, officer or government system is contacted.
  • There is no real registration, password, OTP, CAPTCHA, appeal or legal remedy.
  • Departments, categories and responses are representative examples, not an authoritative directory.
  • Status changes are demonstrative and do not reflect any real grievance lifecycle.
  • The login mechanism is a local demo cookie, not identity verification.
Official portal

For a real grievance, use the official CPGRAMS portal at pgportal.gov.in. This project has no affiliation with DARPG, NIC, MeitY or any government body.

Technology stack

The local environment on this Linux machine does not have the .NET/ASP.NET runtimes required by the production CPGRAMS stack. The demo therefore uses a modern local stack:

BackendPython 3 · FastAPI · server-rendered Jinja2
DataSQLite with constraints and transactional reference allocation
FrontendHTML5 · CSS3 · progressive vanilla JavaScript
Testingpytest · FastAPI TestClient · live HTTP checks

This is a modern local implementation and not the confirmed production stack of the official website.

Data honesty

Seeded records are fictional. User-created records are labelled as local demo submissions. The interface repeatedly states that no real grievance is filed. The optional dashboard adapter is disabled unless an operator explicitly configures an authorised local endpoint and token.
